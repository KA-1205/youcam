# Planning and task execution
Read /SKILLS.md, /IMPLEMENTATION_PLAN.md, /TICKETS.md and the product ZIP from the docs branch first. The product spec wins on conflicts. Identify lane ownership, dependencies, acceptance criteria and focused verification for the next ticket. Keep changes within 1–5 files where possible; split larger tickets. Use a dependency checkpoint before starting. Never edit the docs branch or add undocumented features. Record blockers in your response or GitHub issue, not by rewriting documentation. Complete one ticket, test it, commit it, then proceed.
